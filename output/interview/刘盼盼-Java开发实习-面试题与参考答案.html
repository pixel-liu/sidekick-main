一、面试使用说明

事实边界

简历写到 IntelliDoc 的 Spring Boot、Security、Tika、ES、MinIO、Kafka、Redis、WebSocket；仓库可核验的是 Sidekick 的 Java 17 CLI、Agent、RAG、MCP、HITL、Memory、Web、Runtime API 等。答案中的实现要让候选人用自己的真实代码确认。

判断方法

每题先听主答案，再问“哪个类负责”“失败时状态怎么变”“有什么指标或测试”。能讲链路和取舍，才算掌握；只复述名词不算。

建议时长

项目总览 8 分钟；Java/Spring 20 分钟；Sidekick 25 分钟；IntelliDoc/RAG 20 分钟；场景 10 分钟。

评分建议：基础 30%，Sidekick 30%，IntelliDoc/RAG 25%，工程素养与真实性 15%。

二、项目总览与真实性

1

请画出 Sidekick 从输入到回答的完整链路，并指出你负责的模块。

必问
参考答案：CLI/TUI 接收普通输入或斜杠命令；PromptAssembler 按 base、personality、mode、approval、runtime context、project context、skills、context management 组装提示词；ReAct Agent 执行 LLM 请求、工具调用、结果回灌和终止判断。复杂任务进入 PlanExecuteAgent，由 Planner 生成 Task/DAG，用户确认后交给 Worker；Multi-Agent 由 AgentOrchestrator 协调 Planner、Worker、Reviewer。工具执行前经过 PathGuard、CommandGuard、HITL，执行后审计，最终由 renderer 输出。候选人必须说出自己写过的类、接口、测试和 Bug。
追问：LLM 超时、工具失败、用户取消分别在哪里处理？哪些状态需要持久化？
2

Sidekick 和普通聊天机器人相比，工程难点是什么？

项目理解
参考答案：它是有状态、可执行、有副作用的循环系统，需要工具 schema、参数校验、上下文预算、任务恢复、并发取消、权限审批、审计和可观测性。难点不在“请求模型”，而在模型不确定时仍让系统行为可控、可恢复、可解释。
追问：模型连续调用同一工具时，如何检测循环并停止？
3

请用一次提交或一个 Bug 证明你的个人贡献。

真实性
参考答案：合格回答应包含具体文件/类、输入输出、改动前现象、根因、修复、测试命令和结果。例如说明 `PlanExecuteAgent` 的 DAG 执行、`CodeRetriever` 的混合召回、`McpServerManager` 的 server 状态变化，而不是泛泛说“负责架构”。
风险信号：说不出类名、状态字段、异常、测试名称或具体取舍。

三、Java 17、并发与 Spring

4

volatile、synchronized、CAS 的区别是什么？在取消和任务状态中如何用？

并发
参考答案：volatile 保证可见性和部分有序性，不保证复合操作原子性；synchronized 提供互斥、可见性和可重入；CAS 通过比较交换更新，但有自旋、ABA 和高竞争问题。取消标志可用 volatile/AtomicBoolean；任务从 enqueued 到 running 应采用数据库条件更新或版本号，不能只靠内存变量，否则多 Worker 或重启后会重复领取。
追问：为什么 ConcurrentHashMap 仍不能保证“先 get 再 put”的业务原子性？
5

ThreadLocal 有什么用途和风险？

Java
参考答案：可保存 requestId、用户上下文等线程范围数据；线程池复用时必须 finally remove，否则会串请求或长期持有对象。异步线程切换后普通 ThreadLocal 不会自动传播，应显式传递上下文。
6

阻塞 IO、异步 IO 与并行工具调用如何取舍？

IO
参考答案：阻塞 IO 占用线程等待网络/进程；异步模型提高连接利用率，但仍要处理超时、背压、取消和关闭资源。批量 tool_calls 应用受控线程池/异步执行器，设置单工具和批次超时，最后按原始 tool_call 顺序回灌结果。
7

Spring Boot 自动装配、IOC、AOP 如何工作？

Spring
参考答案：IOC 由容器管理对象和依赖；自动装配根据 classpath、配置和已有 Bean 的条件注册默认实现；AOP 把日志、事务、鉴权等横切逻辑织入代理。排障看扫描、条件是否命中、代理是否生效；类内 `this.method()` 调用通常绕过代理，因此事务/切面可能不生效。
8

MySQL/SQLite 如何设计任务、会话和代码索引？

数据建模
参考答案：任务表至少含 id、内容、状态、版本、时间、错误和重试次数，领取用条件更新；会话区分短期消息和长期事实，并按项目/用户隔离；代码索引保存文件 hash、chunk、语言、符号、行号、embedding 和关系。SQLite 适合本地单机，但并发写入有限，要有事务边界、索引和忙等待策略。
9

Redis Bitmap 为什么适合分片上传？

Redis
参考答案：fileId 对应 bitmap，chunkNo 对应 bit，SETBIT/GETBIT 能低成本记录已上传状态。它不能替代 MinIO/数据库事实；最终合并前仍需校验对象、数量、大小、MD5。key 要隔离租户和文件并设置 TTL；并发完成需 Lua、锁或条件状态更新。
10

Kafka 重复、乱序、积压分别如何处理？

Kafka
参考答案：重复是常态，按业务唯一键幂等；同一文件用 fileId 做 partition key，保证分区内相对顺序；积压看 lag、消费耗时、分区数和下游瓶颈，再扩容或拆阶段。offset 应在业务成功后提交，失败进入重试/DLQ；“exactly once”不等于端到端绝不重复。
11

JWT + RBAC 如何防止越权？

安全
参考答案：过滤器验签名、过期、issuer/audience 等 claims，把身份放入 SecurityContext；接口控制权限，查询层还必须加 tenant、组织和文档 ACL。不能仅靠前端隐藏按钮；refresh、吊销、密钥轮换和敏感操作二次确认也要考虑。

四、Agent、DAG、Multi-Agent 与上下文

12

ReAct 与 Plan-Execute 如何实现？为什么同时保留？

核心
参考答案：ReAct 每轮根据上下文动态决定工具，适合探索任务但路径和 token 不稳定；Plan-Execute 先生成结构化 Task/DAG，经用户确认后执行，适合多步骤、可并行、可恢复任务。工程上限制最大步数、节点数、token 和工具权限，并持久化计划与节点状态。
追问：节点失败如何只重试失败节点？有文件副作用时怎样幂等？
13

Planner、Worker、Reviewer、Orchestrator 的边界是什么？

协作
参考答案：Planner 拆解目标、依赖和验收条件；Worker 执行并返回证据；Reviewer 检查需求、测试和风险；Orchestrator 管理消息、预算、重试和冲突。Reviewer 不能只返回“通过”，要指出文件、测试和残留问题。
14

并行工具调用怎样避免冲突并保证顺序？

并发
参考答案：互不依赖且无共享副作用的调用才能并行；写同文件、共享资源或有前置结果的调用串行。工具层可并发执行，但按原始序号整理回灌；每调用带超时、取消、tool_call_id、错误类型和可重试标记。
15

上下文压缩和 TokenBudget 保留什么、丢弃什么？

上下文
参考答案：保留用户目标、约束、未完成任务、关键工具结果、错误和决策；压缩重复日志、完成步骤和低价值大文件。摘要要区分事实与推断。预算需给输出、工具结果和重试预留空间，接近窗口前提前压缩。
16

短期记忆、长期记忆、PAI.md 项目记忆如何区分？

Memory
参考答案：短期服务当前对话；长期只保存明确要求记住的稳定事实；PAI.md/`.Sidekick/PAI.md` 适合团队规则，local 文件适合本地覆盖。必须按作用域隔离，不能把临时文件名或一次性任务存成长期事实，并支持搜索、删除和清空。
17

HITL、PathGuard、CommandGuard、AuditLog 分别防什么？

安全
参考答案：PathGuard 防绝对路径逃逸、`..` 穿越和符号链接逃逸；CommandGuard 在审批前拒绝危险命令；HITL 让用户批准、拒绝或修改；AuditLog 记录脱敏参数、结果、审批者和时间。它们不是进程级沙箱，不能把路径围栏说成容器隔离。

五、代码搜索与 RAG

18

为什么代码检索同时需要 glob/grep、AST、向量检索和关系图？

RAG
参考答案：glob/grep 擅长精确定位；AST 能识别类、方法、调用、注解和作用域；向量找语义相似；关系图补充 extends、implements、imports、calls、contains。Sidekick 的设计是精确检索优先、search_code 作为语义辅助，避免完全依赖向量导致定位不准。
19

Embedding、KNN、BM25、Rescore 如何组合？

排序
参考答案：向量找语义近邻，BM25 对类名、方法名、错误码和专有名词更敏感；先扩大召回，再归一化分数、融合或 rerank，最后做权限过滤、去重和上下文截断。不能直接比较不同检索器的原始分数。评估用 Recall@K、MRR/NDCG、引用准确率、延迟和 token 成本。
追问：如何构造 deterministic golden set？如何定位是召回失败还是生成幻觉？
20

代码/文档切片大小怎么选？

切片
参考答案：优先按文件、类、方法、标题和段落切；过长结构再窗口切并保留父文档、标题、权限、版本等元数据。过小丢上下文，过大降低精准度并浪费 token。切片边界和元数据直接决定检索能否给出可引用、可验证的答案。
21

JavaParser 解析失败或遇到新语法怎么办？

AST
参考答案：按项目 Java 版本配置 parser，捕获异常并记录文件与位置；失败文件降级为文本索引，不能拖垮整个索引。用文件 hash 做增量更新。单文件 AST 不能完整推断跨模块语义，要明确本地语法关系和全局关系的边界。

六、IntelliDoc：上传、权限与流式问答

22

Kafka + Redis Bitmap + MinIO 的分片上传完整流程？

核心
参考答案：创建 upload session 返回 fileId、chunkSize 和凭证；分片进入 MinIO/队列，Kafka 携带 fileId、chunkNo、size、md5；消费者校验并幂等更新 Bitmap/数据库；全部齐后核对数量、大小、MD5，合并对象并更新完成状态。失败重试，超过阈值进 DLQ，后台补偿。
23

解析、切片、Embedding、ES 写入为什么异步化？

异步
参考答案：这些阶段耗时且受 IO/模型限制，Kafka 可解耦并快速返回“受理中”。每阶段要有状态机、幂等键、重试和失败原因；查询只读已完成/已发布版本；WebSocket 可推送进度。必须考虑重复消费、毒消息和下游限流。
24

SSE 与 WebSocket 如何选择？WebFlux 要注意什么？

网络
参考答案：SSE 是 HTTP 上的单向事件流，适合 LLM token 增量输出；WebSocket 双向，适合上传进度、交互控制和多事件通道。WebFlux 要处理背压、心跳、代理缓冲、超时、客户端断开和上游取消，断开后必须释放模型连接并保存已生成内容。
25

权限过滤放在检索前还是检索后？

越权
参考答案：两者都做：检索 query 必须带 tenant/ACL，防止无权文档被召回；最终拼接上下文、缓存读取和答案引用前再次校验，防止权限变化或缓存造成越权。前端隐藏按钮不是安全边界。
26

RAG 答案“相关但不能用”如何定位？

质量
参考答案：记录 query、权限、候选、分数、上下文、模型版本和引用；分别判断切片边界、召回、排序、权限、提示词还是模型幻觉。改进可用标题增强、父子块、混合检索、去重、rerank、引用约束和拒答。用固定评测集和线上延迟/成本共同验证。

七、Web、MCP、LSP、Runtime API 与测试

27

web_fetch 为什么对 SPA/防爬站点失败？

Web
参考答案：OkHttp 只拿初始 HTML，SPA 内容由 JavaScript 执行生成，防爬可能返回挑战页。基础路线是 OkHttp + Jsoup + readability；识别正文为空或挑战页后 fallback 到 Chrome DevTools MCP，通过导航和 DOM snapshot 获取内容。还要限制 file、内网、loopback、大小、超时和频率。
28

MCP 的 stdio 与 Streamable HTTP 有何区别？

MCP
参考答案：stdio 通过本地子进程 stdin/stdout 传 JSON-RPC，适合本地 server；HTTP 适合远程 server，需要鉴权、超时和重连。初始化后根据 capability 注册工具和 resources，处理 tools/list_changed；schema 要清洗 `$ref`、`anyOf` 和超长描述。MCP 工具仍需 HITL、审计和凭证脱敏。
29

write_file 后的 LSP 诊断注入有什么价值？

LSP
参考答案：写入后做轻量语法诊断，把 error/warning/info、文件、行列和消息在下一轮注入模型，帮助自动修复。诊断失败不能阻塞写文件，因此采用 pending report、条数上限和非阻塞注入；未来可接 JDT LS 等真正语言服务器。
30

Runtime API 的 thread、turn、event 如何设计？

API
参考答案：创建 thread 后，turn 启动 Agent run；event stream 推送模型增量、工具调用、结果、错误和完成事件。事件应含 event id、thread id、时间和类型，断线可按游标重放或明确终态。API key 在服务端校验且不写日志，取消要打通 CancellationToken。
31

如何用测试证明项目可靠？

测试
参考答案：基础层测 parser、预算、状态机和策略；Agent 层用 fake LLM/fake tool 验证顺序、重试、取消；RAG 用 golden set 验证检索；Web/MCP 用 mock server 验证超时、fallback、JSON-RPC 和通知；按 smoke、quick、全量分层运行。每个 Bug 要能给出复现输入和修复断言。

八、综合场景题

32

线上出现 Agent 重复修改同一文件，如何排查和止损？

参考答案：按 requestId/turnId 查看消息、tool_call、文件 hash、快照和审计，区分循环、并行冲突、重试非幂等或旧上下文。止损是暂停写工具、恢复快照、限制同文件并发、加入内容版本校验和最大步数；修复后补冲突测试和指标。
33

Kafka 积压且上传进度不变，如何定位？

参考答案：检查 consumer lag、分区热点、消费耗时、失败/重试/DLQ、Bitmap、MinIO 和数据库状态。按 key 修复热点，拆分慢的解析/Embedding 阶段，隔离毒消息；进度接口区分未消费、处理中、失败和完成，而不是只返回百分比。
34

未知代码库中如何让 Agent 做安全变更？

参考答案：先读项目规范和构建入口，精确搜索后再语义检索；先计划并确认范围，修改前快照，小步变更，写后诊断和相关测试；危险命令审批，变更后检查 diff、测试和残留风险。核心是最小权限、可回滚、可验证。

九、最终评价

结论标准
强烈推荐能画清两个项目的数据流和状态；理解并发、权限、幂等、RAG 评测和安全边界；能用类名、代码、测试和指标举证。
推荐基础扎实，至少一个项目深入到实现细节；部分中间件原理需培养，但排障思路完整。
谨慎术语覆盖面大，却说不出关键字段、失败路径、指标和测试。
不推荐混淆 JWT/RBAC、Kafka exactly-once、RAG 召回与生成，或把路径校验说成沙箱隔离。
依据：用户提供的简历 PDF 与 Sidekick 项目仓库 README/源码结构整理。IntelliDoc 的具体代码未在当前仓库中，面试时应要求候选人现场展示真实实现。
